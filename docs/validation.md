## 存储卡交换区优先级

独立版的原有策略是 zRAM 优先级 100、TF 卡优先级 10。本版新增相同优先级选项，两处都设为 100，沿用原有 2 GiB 交换文件。升级后原有虚拟内存开关会保留，优先级初始采用原策略。操作和复核命令见[虚拟内存设置](build.md#配置-2-gib-存储卡交换区)。

在一台使用开源图形驱动和 75% zRAM 的 GKD Pixel 2 上，用官方版吉里吉里 1.4.4 的 OpenGL 模式载入《千恋＊万花》。两轮都从空的 TF 交换区开始。约 88 秒时，TF 默认优先级 10 的占用峰值为 0 MiB，同优先级 100 的峰值为 86.3 MiB。同期整张卡的累计写入分别为 4.7 MiB 和 159.5 MiB。相同优先级的首次载入在 225 秒内未验证到标题画面，因此单列为载入测试。

另一次在默认档进入第一章，验证章节标志后将 TF 优先级临时调为 100。160 次输入后，同一游戏进程仍可响应。又送入 28 次输入，观察到街景切换为人物出场，整段 TF 交换区占用峰值为 70.4 MiB。延长段最后两次采样的画面相同。此轮未记录到游戏进程因低内存退出或无响应；两档测试期间均观察到系统界面进程反复重启，长时间游玩和其他存储卡的表现仍待验证。

与该掌机系统匹配的镜像在独立虚拟卡上验证了四次启动。TF 交换区依次为关闭、优先级 10、优先级 100、优先级 100。设置在重启后生效，zRAM 全程保持优先级 100，四次关机均正常卸载数据卷。

## v0.3.1 AT4K 双驱动镜像

最初的候选版在 119 GiB 卡上启动后同时列出了 AT4K 和 Trebuchet。实机读数显示手柄辅助服务尚未启用，导航栏处于显示状态。修正版在系统主屏角色与新用户初始设置中处理这两项缺省值。AT4K 保留原 APK 签名，系统壁纸与 H700 安装包中的原图逐字节相同。

在同一张卡上启用手柄服务后，用内置手柄转发设备送入间隔 50 毫秒的 R1 和功能键，实机显示返回、桌面和最近任务菜单。已确认方向键移动 AT4K 的应用焦点，A 打开文件管理器，B 返回桌面。在最近任务中，左、右键切换设置和时钟，X 移除选中的时钟任务，B 返回 AT4K。概览显示了可用物理内存、总量和 TF 交换状态。

Windows 助手与独立组装流程分别生成了相同的 7 GiB 整卡，SHA-256 均为 `0bd96facdf47b3670c5e362fe40456ba85976e72f8bc22ecbbd47355ecb05e17`。修正版通过了 ARM 虚拟卡的默认 Mesa、试用 Mali 和未确认后回退 Mesa 三轮启动检查。

全新刷卡后，首次解锁应直接进入 AT4K，系统右侧三键栏应隐藏，R1＋功能键可直接打开导航。若要复核实际主屏、原图校验值和手柄服务绑定状态，可在只启用 USB 调试后运行下面的只读检查。它会把手动更换过默认桌面或关闭手柄服务的设置报告为偏离出厂状态。实机画面和首次开机的结果见本版发布说明。[v0.3.1 发布记录](https://github.com/JackyChenXY/gkd-pixel2-gammaos/releases/tag/v0.3.1)

```sh
python3 port/desktop/at4k/check-device.py
```

## v0.3.0 整卡检查

Windows 安装助手已在 Windows x64 上生成 7 GiB 双驱动镜像。独立实现逐项验证了 11 个驱动文件、完整的 128 MiB 备用 vendor 和启动选择扇区。Windows 生成的镜像读回 SHA-256 与独立实现一致。公开基础镜像使用空槽和默认 Mesa，两个镜像的数据分区均为首次开机准备的空白状态。

同一张虚拟卡已通过六次启动检查，依次覆盖出厂预装、首次试用、未确认回退、确认保留、保留后再启动和手动返回 Mesa。Android 图形设置服务每次都返回了预期状态。真实面板显示、Mali 冷启动以及具体游戏性能仍需在 GKD Pixel 2 上复测。下文的实机体验来自这台掌机上此前测试的相应组件。

## 复核

设备启动完成、解锁并授权 USB 调试后，可从电脑检查：

```bash
adb shell getprop sys.boot_completed
adb shell getprop ro.lineage.version
adb shell getprop ro.gsid.image_running
adb shell getprop ro.crypto.metadata.enabled
adb shell cat /proc/swaps
adb shell cat /proc/meminfo
```

完成独立启动时，`sys.boot_completed` 应为 `1`，`ro.gsid.image_running` 应为 `0`。`MemTotal` 表示内核可用物理内存，`SwapTotal` 表示交换空间总量。两种交换设备可用 `/proc/swaps` 分辨。对离线的 `system.img` 可运行 `e2fsck -fn`，对打包后的 `super.raw.img` 可用 `lpdump --slot=0` 和 `lpdump --slot=1` 核对两个逻辑分区表。

## 已知限制

- 当前为 `userdebug/test-keys` 构建，Android 安全补丁日期为 `2023-11-05`。SELinux 使用 permissive，尚未建立完整的 AVB 强制验证链。USB 调试使用设备端授权。
- 交换文件位于启用元数据加密的 F2FS 数据卷中。开启后会占用 TF 卡空间。本次对照使用同一张卡，其他卡速及模拟器负载仍待验证。
- 实机验证基于一台 GKD Pixel 2。不同屏幕批次和存储卡的兼容性待验证。

## 开源驱动实机结果

- 116.5 GiB 测试卡已用 Mesa 24.3.4 冷启动到桌面，原版 glmark2 完成 33 个场景。系统使用 Panfrost，GLES 1、2、3 的像素读回和 ES 3.1 计算结果均已核对。[驱动、对照条件和测量值](../port/open-variant/vendor/pixel2-system-gpu/)
- Quickstep 最近任务已在实机显示物理内存可用量和 TF 卡交换用量，可用手柄切换和关闭所选任务。内存解析测试覆盖空表、关闭、低于 1 MiB 以及启用两种交换优先级的情况。[截图与操作说明](components.md)
- 已在参考安装验证官方吉里吉里 1.4.4 的图标启动和《千恋＊万花》自动剧情。驱动、APK 散列和参考安装 UID 是此次测试的版本条件。[兼容目录](../port/open-variant/krkr2/)

### 桌面和渲染组件的离线复核

两个 APK 都通过 Android 签名验证。Trebuchet 的四个补丁按顺序应用到原版源码，八项内存计数测试全部通过。下载包中的系统驱动组装器在匹配的 vendor 镜像上检查了 914 个条目、五个 ARM32 图形库、GLES 3.1 声明和 SELinux 标签。吉里吉里修复的 system 组装器检查了基线中 4,933 个条目，并验证 ext4、AVB 签名和纠错数据。两次组装均在电脑上操作普通镜像文件。

此前曾出现桌面系统设置图标名称错误。参考机上刷新 Android 为 Settings 保留的旧资源编号缓存并重启界面后，桌面恢复了正确名称。新安装或其他固件的缓存状态可能不同。
